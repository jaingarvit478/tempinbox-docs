## Hosted service

TempInbox at [tempinbox.dev](https://tempinbox.dev) is a browser-based, receive-only temporary inbox service. It does not currently offer a supported public automation API. Internal browser endpoints are not a stable integration contract, and exporting browser access tokens is not a supported CI workflow.

For hosted use, start with [email verification QA](/guides/qa-workflows), [multiple inboxes](/guides/multiple-inboxes), and [inbox lifetime](/guides/inbox-lifetime).

## Self-hosted implementation examples

The endpoint reference and framework examples describe implementation concepts for an instance you operate. Check them against the code and version you deploy. Some legacy examples can differ from the current implementation; there is no compatibility guarantee for the hosted site's internal endpoints.

Replace the illustrative `https://your-worker.example.com` with your own deployment URL and configure inbound mail routing, authentication, Turnstile, and rate limits deliberately. The examples are not a service that receives mail merely by copying a URL.

A deployment may require a valid Turnstile token when creating an address. Existing address access uses a signed token; knowing the address alone is insufficient. Keep test credentials in your test runner's private configuration and do not log verification tokens.

## Choosing automation infrastructure

For unattended tests, use a supported API-capable mail-testing provider or a controlled capture system. Create a unique recipient per run, wait with a bounded timeout, and match the current recipient, sender, subject, and timestamp before extracting a code.
